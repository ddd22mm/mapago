## 구현 범위

- 사용자 1명(동가·친)과 AI 3명의 동1국 연습. tenhou/mjsoul 규칙과 기존 두 봇 정책을 선택한다.
- 패 선택/타패, 엔진이 허용하는 치·퐁·깡·리치·화료·패스·구종구패 행동을 표시한다. 같은 종류라도 대상/소비 패가 다른 호출을 구분한다.
- 손패, 상대 패 뒷면, 후로, 버림패, 점수, 국/본장/공탁, 도라 표시패, 남은 패 수와 대국 흐름을 표시한다.
- 사용자 입력 후 봇 차례를 진행하고 다음 사용자 의사결정 시점에 멈춘다. 동시 응답창에서도 사용자 선택을 받은 뒤 모든 활성 좌석 행동을 함께 적용한다.
- 한 국 종료 결과와 점수 변화, 다음 연습, 내 좌석 JSON 복기 내려받기를 제공한다.
- 새로고침으로 현재 세션 대국을 다시 읽고, 오래된 국면 요청은 충돌 오류로 거부한다.
- 마우스와 키보드(좌우 선택, D 타패, Esc 패스), 네이티브 dialog, 접근성 레이블과 상태 알림을 추가했다. 반응형 CSS를 작성했으나 실제 크기별 렌더링은 아직 확인하지 못했다.

## 기술 결정

빌드 없는 HTML/CSS/JavaScript와 Python 3.12 표준 라이브러리 HTTP 서버를 로컬 프로토타입으로 선택했다. 기존 프로젝트에 Node나 프론트엔드 프레임워크가 없고, 이번 범위는 단일 사용자의 한 국 입력·결과 반환이어서 새 의존성 없이 검증할 수 있다. React/FastAPI/WebSocket은 운영 구조가 필요해지는 시점에 재검토하며 현재 의존성에 추가하지 않았다.

Sites skill의 로컬 개발 경로를 적용했다. 기존 저장소 지침상 배포는 범위 밖이므로 사이트 등록·게시·원격 호스팅은 하지 않았다. 외부 그림·폰트·모델·데이터를 추가하지 않았고 패 얼굴은 자체 CSS/SVG로 표현했다.

`GameSession`은 HTTP와 무관하게 사용자/봇 진행을 조정한다. 2단계 `MatchEngine`과 기록 형식을 재사용하고 사용자 좌석 정책은 `human` 버전 1로 기록한다. 완료된 내부 기록은 기존 `replay()`로 검증할 수 있다. 공개 API가 시드나 상대 패를 받거나 반환하지 않도록 했다.

## 직접 실행 (개발/분석 보조 경로)

일반 대국 화면은 아래 Docker Compose 경로를 사용한다. 이 직접 실행 명령은 엔진 분석과 로컬 API 디버깅을 위한 보조 경로다.

```powershell
.\.tools\uv.exe run --locked python -m mapago_tools.server
```

`http://127.0.0.1:8765`에서 시작한다. `--port 8766`처럼 포트를 바꿀 수 있다. 서버는 127.0.0.1에만 바인딩한다. 종료는 Ctrl+C다.

## Docker Compose 실행 환경

환경 의존 실행 문제를 해결하기 위해 Docker Compose를 기본 실행 경로로 추가했다. `python:3.12.15-slim-trixie`, `uv 0.13.6`, `uv.lock`의 고정 의존성으로 이미지를 빌드한다. 개발 도구와 로컬 가상환경은 이미지에 포함하지 않는다. 이 변경은 애플리케이션 의존성/API 구조를 바꾸지 않는다. 직접 Python/uv 실행은 엔진 조사와 테스트용 보조 경로로 유지한다.

검토한 대안은 각 PC에 Python/uv를 따로 설치하는 방법(환경 차이가 재발할 수 있음)과 React/FastAPI/WebSocket 도입(현재 단일 사용자 프로토타입 범위보다 큼)이다. Windows 실행에는 Docker Desktop의 WSL 2 백엔드와 BIOS/UEFI 하드웨어 가상화가 필요하다.

`docker compose up --build -d`로 빌드/시작하고 `docker compose down`으로 종료한다. 포트 8765 충돌 시 `MAPAGO_PORT=8766`으로 바꾼다. 서버는 컨테이너 안에서 `0.0.0.0:8765`에 바인딩하지만, Compose가 호스트의 `127.0.0.1`에만 포트를 게시하며 Host/Origin 검사는 `127.0.0.1:<공개 포트>`와 일치하는 요청만 받는다.

## API와 세션 경계

| 경로 | 동작 |
| --- | --- |
| `GET /`, `/app.js`, `/styles.css` | 명시적으로 허용한 UI 파일만 제공 |
| `POST /api/game` | 규칙/봇 정책으로 새 한 국 생성, HttpOnly·SameSite=Strict 세션 쿠키 발급 |
| `GET /api/game` | 쿠키의 대국에서 내 좌석 상태만 읽기 |
| `POST /api/action` | `revision`, `action_id`를 확인한 뒤 합법 행동 적용 및 봇 진행 |
| `GET /api/replay` | 완료된 대국의 내 좌석 복기 반환 |

메모리에 최대 32세션, 세션 유효기간 4시간을 둔다. 같은 쿠키에서 새 대국을 만들면 이전 세션을 대체하며 서버 재시작 후에는 복구하지 않는다. 요청 처리는 잠금으로 직렬화하고 이전 revision·중복 입력·잘못된 인덱스를 거부한다. 내부 archive와 패산/시드, 상대 손패, 상대 쯔모 원본을 응답하지 않는다.

서버는 Host와 POST Origin을 로컬 주소와 대조하고 JSON 요청 크기를 제한한다. 정적 파일 allowlist로 저장소·artifacts 경로를 노출하지 않으며 응답은 no-store, CSP와 프레임 차단 헤더를 사용한다. 이것은 계정 인증·멀티플레이 서버가 아니며, Python http.server는 운영 배포용으로 선정하지 않았다.

## 실제 검증

전체 `unittest` **28개 통과**: 기존 20개 + 3단계 8개.

- 두 규칙 × 두 봇 정책에서 사용자 행동을 반복 제출해 한 국을 완료하고 2단계 기록 재생과 점수를 대조했다.
- 고정 실험 seed 42에서 23회 사용자 선택 / 88 step / 유국 종료 / 전원 25000점을 확인했다. 전체 이벤트 해시 `28c70704043896e774b226455afa623f7af8a95baf9bc4d9bd70042d6cfc88b1`.
- 사용자 좌석에 실제 제공되는 가깡(seed 1), 대명깡(81), 암깡(113), 론(163), 구종구패(412), 리치(948)를 선택해 적용하고 전체 기록을 재생했다. 쯔모 화료 UI 조작은 별도로 검증하지 않았다.
- 실제 HTTP 서버에서 쿠키를 받아 행동을 제출해 한 국 완료, 결과와 내 좌석 복기 JSON을 확인했다.
- 상대 정보 은닉, 임의 시드 입력 거부, 세션 분리/교체/새로고침 읽기, 오래된 요청 409, 잘못된 행동 400, 무세션 404, Host/Origin 오류 403, 정적 경로 차단을 확인했다.
- 홈페이지 HTTP 200과 정적 자산 응답을 확인하고 Node VM으로 `app.js` 구문 검사를 통과했다. Windows 셸 PATH의 Node 설치 없이 제공된 Node 실행 도구로 구문만 검사했다.

요약 결과는 `docs/validation/stage3-game.json`에 기록했다. `verified`는 엔진 기록 재생의 검증이며 `browser_verified`는 false다.

## 브라우저 확인 제한

Computer Use의 브라우저 인벤토리가 `The browser access host is unavailable`을 반환했다. 이어서 네이티브 Chrome 선택도 **현재 브라우저 URL을 충분한 신뢰도로 확인할 수 없어 정책을 적용할 수 없다**며 이 턴의 Computer Use를 중단했다. 도구 지시대로 추가 UI 입력을 하지 않았다.
