# 2단계: 4개 봇 자동 대국과 기록 저장·재생

완료일: 2026-10-28. 기준: Notion 「4인 AI 자동 대국 및 로그 재생 기반 구축」의 대국 종료·결과·이벤트 재생 조건.

## 구현

- `bots.py`: 좌석별 독립 인스턴스와 난수 상태. `first-legal` 및 `random-legal`, 각각 정책 버전 1. 봇은 자신의 관측 DTO와 엔진 합법 행동만 받고 선택한 인덱스를 반환한다. 실력·난이도 프로필은 아직 구현하지 않는다.
- `match.py`: 엔진 어댑터, 4봇 실행, 내부 기록 저장, 기록 검증과 좌석별 복기 프레임 생성. 기존 RiichiEnv 0.4.11과 Python 표준 라이브러리만 사용하며 새 의존성은 없다.
- `kyoku`, `east`, `hanchan` 모드 및 tenhou/mjsoul 프리셋, 시작 친과 봇 조합을 지원한다. 호출 응답은 동시에 활성화된 모든 좌석의 행동을 한 배치로 적용한다.
- 엔진이 제공한 행동 객체와 동일한 데이터인지 적용 직전에 검증한다. 잘못된 봇 인덱스·중복 좌석·누락 좌석·비합법 행동·진행 상한 초과는 실패한다.
- 봇이 마지막으로 결정한 이후의 이벤트를 좌석마다 누적해 전달한다. 다른 관측 읽기가 엔진 이벤트 커서를 소비해도 봇에 필요한 이벤트가 누락되지 않는다.

## 저장 결정과 대안

초기 구현은 버전이 있는 로컬 JSON 파일을 사용한다. 이 단계에서 DB·WebSocket·HTTP 서버를 추가할 필요가 없어 선택했다. JSONL 스트리밍이나 DB는 장기 보존·중단 복구·동시 사용자 요건이 정해진 후 검토한다. 기본 실행 상한은 20,000 step이며 전체 기록을 메모리에 보유한다.

`mapago.match.v1` 내부 기록:

| 필드 | 역할 |
| --- | --- |
| `visibility` | `internal-only` 표시 |
| `engine` | 엔진 이름과 정확한 버전 |
| `config` | 모드·규칙 프리셋·시드·시작 친, 좌석별 정책 이름·버전·난수 시드 |
| `initial` | 초기 상태 검증 해시와 전 좌석 손패/쯔모를 가린 이벤트 |
| `steps` | 단계 순번, 활성 좌석별 실제 행동, 적용 후 검증 해시와 순번 있는 공개 이벤트 |
| `result` | 점수·순위·국 수·행동 수·이벤트 집계와 전체 원본 이벤트 해시 |
| `sha256` | 기록 내용의 일관성 검사 |

원본 전지적 MJAI 이벤트나 패산을 그대로 디스크에 쓰지 않는다. 다만 시드와 행동만으로 비공개 패를 복원할 수 있으므로 **내부 기록 자체는 비공개 데이터**다. `*.internal.json`과 `artifacts/`는 Git에서 제외했다. 파일명과 visibility 표시는 접근 제어가 아니다. 서버를 연결할 때 내부 기록 경로를 정적 파일로 제공하지 말고, 인증된 좌석에 해당하는 뷰만 제공해야 한다.

원본 기록을 검증한 뒤 새 파일을 배타적으로 생성해 기존 결과를 덮어쓰지 않는다. SHA-256은 우발적인 변경·재현 불일치를 찾는 용도이며 서명/인증 기능이 아니다. 프로세스 강제 종료·디스크 쓰기 실패 시 생길 수 있는 불완전 파일은 재생 시 거부되며, 중단 지점 재개는 이번 범위에 포함하지 않는다.

## 재생 방식

단순히 같은 봇을 같은 시드로 다시 돌리는 1단계 방식과 다르다.

1. 파일의 스키마·체크섬·엔진 버전과 설정을 검증한다.
2. 기록한 시드·프리셋·모드·시작 친으로 새 엔진을 초기화한다.
3. 저장된 행동을 해당 시점의 합법 행동과 정확히 대조해 적용한다. 봇 코드를 호출하지 않는다.
4. 각 step에서 네 좌석의 관측 상태와 새 원본 이벤트, 종료 여부의 해시 및 저장된 공개 이벤트를 대조한다.
5. 대국 종료 여부, 최종 점수·순위·국 수·이벤트 해시를 대조한다.

같은 시드라도 잘못된 행동·이벤트·상태·결과가 저장되면 실패한다. 엔진 버전이 다르면 임의 변환하지 않고 거부한다. 저장된 MJAI 텍스트만 `apply_event`로 흘리는 대안보다 실제 엔진 행동·동시 호출 응답을 다시 검증할 수 있어 이 방식을 선택했다. 임의의 외부 MJAI 기록 가져오기는 지원하지 않는다.

## 좌석별 복기

`replay --viewer 0 --output ...`은 검증 성공 후 `mapago.seat-replay.v1` JSON을 생성한다. 프레임은 초기 상태와 각 행동 적용 후 상태, 전역 순번을 가진 해당 좌석 관점의 이벤트다. 손패·후로·버림패·도라·점수·리치·본장·공탁·장풍·친·합법 행동을 포함한다.

- 상대 손패 배열은 비어 있고, 시작 패와 상대 쯔모는 `?`다.
- 공개 행동·화료/유국·점수 변화는 이벤트로 남긴다. 화료 이벤트에 포함될 수 있는 별도 손패 정보는 허용 필드에서 제외한다.
- 내보낼 상태와 이벤트는 허용 필드만 복사한다. 시드·패산·원본 설정·상대 관측을 내보내지 않으며, 알 수 없는 이벤트 유형은 실패한다.
- 모든 좌석의 뷰를 한 사용자에게 제공하면 상대 패를 알 수 있으므로 미래 서버에서 뷰 선택 권한을 검증해야 한다. 현재는 로컬 CLI 도구다.

## 실행과 검증

실행 명령은 README의 「4개 봇 대국과 재생」을 따른다. 이 PC에서는 `uv` 대신 `.\.tools\uv.exe`를 사용한다.

Windows x86_64 / CPython 3.12.16 / RiichiEnv 0.4.11에서 실행했다.

| 검증 | 결과 |
| --- | --- |
| seed 42, random-legal 4개, tenhou 동풍전 | 712 step / 714 결정 / 8국, 4명 25000점, 엔진 순위 1/2/3/4 |
| 파일 저장 후 별도 CLI 재생 | 각 단계 상태·이벤트 및 최종 결과 일치 |
| 이벤트 집계 | 치 37, 퐁 20, 타패 617, 쯔모 560, 유국 8, 시작/종료 국 각 8, 대국 시작/종료 각 1 |
| 원본 이벤트 해시 | `96e07a2737ee49fbc282ed1c0452a52892b2859b558e02ea55c7d1805bfac29c` |
| 전체 자동 테스트 | 20개 통과: 기존 8개 + 2단계 12개 |
| 모드·프리셋 | 3개 모드 × 2개 프리셋에서 완료 후 모든 단계 재생 |
| 특수 이벤트 | 실제 생성한 seed 0 가깡, 2 화료, 18 암깡, 23 리치, 81 대명깡의 저장·재생 확인 |
| 실패 경로 | 기록 손상·잘림·순서 변경·체크포인트/이벤트/결과 변조·잘못된 행동·중복/누락 좌석·잘못된 버전·설정·상한 초과·덮어쓰기 거부 |
| 관측 경계 | 네 좌석의 뷰에서 상대 패/쯔모 은닉, 이벤트 순번 연속성, 봇에 누적 이벤트 전달, 미지 필드 제거 확인 |

요약 결과는 `docs/validation/stage2-match.json`에 저장했다. 내부 기록과 좌석0 복기는 각각 `artifacts/stage2-east.internal.json`, `artifacts/stage2-east.seat0.json`에 있으며 버전 관리 대상이 아니다. 이 시드의 동풍전이 8국까지 진행된 것은 엔진의 종료 조건에 따른 결과다. 최종 제품 종료 규칙과 점수 정답 대조는 별도 검증해야 한다.

개발 중 공식 타입 선언의 `get_obs_py(int)`와 wheel의 실제 시그니처가 달랐고, `Observation.to_dict()`의 후로는 JSON 객체가 아닌 `Meld` 객체였다. 실제 동작하는 `get_observations([seat])`를 사용하고 후로 필드를 명시적으로 직렬화해 해결했다. 다인 응답 회귀 테스트는 동시 호출 창이 실제 발생하는 first-legal seed 42로 고정했다.

## 남은 범위

- 3단계: 사용자 대국 화면과 사용자 행동 연결. 이번 단계는 CLI와 데이터 기반이다.
- 4단계: 샹텐·유효패·수비를 고려한 규칙 기반 정책. 현재 봇은 강도 측정 대상이 아니다.
- 7단계: 사용자 선택/당시 추천의 비교와 코치 분석 스냅샷, 탐색 가능한 복기 UI.
- 운영 저장소·보존 정책, 인증/좌석 권한, 원자적 저장·중단 복구, 버전 마이그레이션, 전체 규칙 경계 국면 정답 대조는 미결정/미검증이다. Linux/macOS는 실행하지 않았다.
