# 작혼 옥탁·왕좌탁 패보 조사

2026-10-29 확인. 제품 의존성 추가나 모델 학습은 수행하지 않았다.

## 실제 접근 확인

[Hugging Face 데이터셋](https://huggingface.co/datasets/nikketryhard/tenhou-houou-mjai)의 API에서 `majsoul-jade-2019.tar`~`2026.tar`, `majsoul-throne-2019.tar`~`2026.tar` 총 16개 파일, 30,755,184,640 bytes(약 30.76GB)를 확인했다. 천봉 파일은 조사 대상에서 제외했다. README에 빠진 2026 파일도 API에는 있다.

각 파일의 앞 512KiB를 HTTP Range로 요청해 모두 206 응답을 받았다. 총 8MiB만 받고 각 파일의 처음 완전한 10대국을 zstd 해제·JSON 파싱했다. 첫 구간의 편의 표본이므로 무작위 표본이나 전체 품질 검증은 아니다. TAR를 디스크에 풀지 않고 멤버를 메모리로 읽었다. 원본 prefix는 Git 제외 `.research/paipu-samples/`에만 보관한다. 압축 해제용 zstandard 0.25.0은 PyPI 공식 휠 SHA256 검증 후 연구용 폴더에만 배치했다.

옥탁 2021~2026 샘플은 첫 쯔모가 초기 14장에 포함되고 첫 타패부터 시작한다. 별도 dora 이벤트가 없는 이유와 다른 필드에 포함되는지는 추가 확인이 필요하다. 깡 수와 도라 수가 반드시 같아야 하는 것은 아니지만 이 형식 차이를 무시하면 학습 관측을 잘못 만들 수 있다. 왕좌탁도 완전한 정합성을 보증하지 않는다.

탁 구분은 배포자의 폴더·파일 분류에 근거한다. 확인한 start_game 필드에는 탁 ID·플레이어 단위 계급이 없으므로 상위 유저 등급이나 원본 출처를 개별 검증한 것은 아니다. 4인전은 손패 배열로 확인했지만 동풍/반장 구분은 원본 메타데이터와 함께 확정해야 한다.

## 추가 확보 경로

- [MajSoul Stats](https://amae-koromo.com/): 날짜·탁·유저로 대국 목록 탐색. 목록·점수 정보와 학습에 필요한 전체 행동 원문은 구분해야 한다.
- [공식 소스의 탁 ID](https://github.com/SAPikachu/amae-koromo/blob/master/src/data/types/gameMode.ts): 4인 옥탁 반장 12, 왕좌탁 반장 16, 옥탁 동풍 11, 왕좌탁 동풍 15. 3인 ID는 별도다.
- [수집·변환 도구 문서](https://github.com/NikkeTryHard/tenhou-to-mjai/blob/main/docs/majsoul-scraper.md): 목록 UUID 탐색 → 작혼 원본 protobuf 다운로드 → MJAI 변환. 원본 다운로드에는 계정이 필요하다. 도구 문서만 확인했고 로그인·직접 수집은 실행하지 않았다.
- [MajsoulPaipuConvert](https://github.com/jeff39389327/MajsoulPaipuConvert): 개발자가 CN 계정 필요·4인 지원이라고 명시한다. 설치·로그인은 실행하지 않았다.

## 이용 조건과 다음 검증

데이터셋 라이선스 표기는 `other`다. 배포 카드의 도구 Apache-2.0 설명을 패보 자체의 학습·재배포 허가로 볼 수 없다. 권리 설명은 천봉 중심이어서 작혼 원본에 관한 조건은 명확하지 않다. 배포 가능·상업 사용 가능으로 확정하지 않았다.

먼저 왕좌탁 소량을 대상으로 원본 UUID·탁 ID·규칙 메타데이터를 대조하고, 이벤트 상태 재구성·합법 행동·점수 검증을 해야 한다. 옥탁의 14장 시작 및 도라 표현은 별도 변환 검증이 필요하다. 학습 입력은 자기 손패와 그 시점까지의 공개 정보만 사용하고 상대 손패·미래 쯔모를 제거한다. 유저 이름은 제거하고 같은 대국 UUID가 학습·검증·테스트에 중복되지 않게 분리한다. 사람의 타패 일치율은 측정 가능하지만 사람 대비 대국 실력과 동일하지 않다.

집계 증거: `docs/validation/majsoul-paipu-sample-audit.json`. 원본 유저명·패보 UUID는 저장소 집계에서 제외하고 파일 식별자는 SHA256으로 기록했다.

## 천봉 봉황탁 데이터 추가 (2026-11-05)

[같은 공개 데이터셋의 Tenhou shards](https://huggingface.co/datasets/nikketryhard/tenhou-houou-mjai)는 2009–2026 연간 TAR 18개로 배포된다. 각 TAR는 비압축이며, 대국별 `.mjai.json.zst` 멤버를 포함한다. Hugging Face API에서 파일 크기를 조회하고 `.research/tenhou-paipu/` 아래 원본 TAR를 받는다. `.research/`는 Git 제외 대상이며 원본 로그와 로그 ID를 커밋하지 않는다. 정확한 로컬 파일 크기·SHA256 및 수신 여부는 별도 집계 보고서에 기록한다.

데이터셋 카드는 라이선스를 `other`로 분류하고 원본 게임 기록은 Tenhou.net (C-EGG)의 제3자 자료라고 한다. 변환 프로젝트 README는 코드에 Apache-2.0이 적용되지만 로그는 제3자 자료이고 CC BY 권리를 부여하지 않는다고 명시한다. 따라서 권리 보유자와 조건을 확인하기 전에는 모델·가중치를 재배포하지 않는다. 라이선스가 불명확한 작혼 샤드의 권리 상태를 천봉 데이터 표기로 대체하지 않는다.

천봉 학습은 `--source tenhou`로 분리 실행하며 `tenhou-imitation-v1` 체크포인트를 생성한다. 학습·검증·보류 테스트 연도 구분(2019–2024/2025/2026), 고정 시드 reservoir sampling, 재생 불일치 대국 통째 제외, 합법 행동 제한을 사용한다. 비교는 천봉 규칙·반장전에서 좌석 순환하며 `rule-based-v1`과 수행한다. 두 사이트의 규칙과 모집단 차이로 직접 순위가 비슷할 것이라는 가정은 검증 전 사실로 취급하지 않는다. 행동 모방률은 대국 실력이나 레이팅이 아니다.

## 학습·비교 완료 (2026-11-05)

### 천봉 봉황탁

- 18개 연간 TAR, 18,102,231,040 bytes를 내려받았다. Hugging Face revision `6450bb584cef43ede3b514df48e301a832c6818b`의 각 파일 크기와 LFS SHA-256을 대조했다. 체크섬 매니페스트는 `docs/validation/tenhou-dataset-manifest.json`이다.
- 2019–2024에서 연도별 120대국씩 720대국을 학습, 2025년 120대국을 검증, 2026년 120대국을 보류 테스트에 썼다. 모든 표본이 천봉 규칙으로 재생됐다. 최종 epoch의 타패 모방 일치율은 학습 44.99%, 검증 44.86%, 보류 테스트 44.72%다.
- 시드 20261105–20261120, 좌석 순환 64반장 비교에서 모방 모델 평균 순위 3.56·평균 점수 변화 -21,786·화료율 1.73% (11/636국), 방총 론 청구 118/636국이었다. 같은 혼합 대국의 규칙 기반 상대군은 평균 순위 2.15·평균 점수 변화 +7,262·화료율 23.53% (449/1,908국), 방총 론 청구 249/1,908국이었다. 표본이 작고 같은 대국 참가자의 결과가 상관되어 있어 레이팅이나 보편적 실력으로 해석하지 않는다.

### 작혼 옥탁·왕좌탁

- 기존 고정 시드 표본은 학습 1,440대국 중 1,096대국(76.1%), 검증 240대국 중 173대국(72.1%), 2026 보류 테스트 240대국 중 156대국(65.0%)만 합법 재생됐다. 재생 실패율은 표본 기준 옥탁 2019 5.8%, 2020 26.7%, 2021–2024 62.5–64.2%였고 왕좌탁은 2019 0.8%, 2020–2024 0%였다. 이는 전체 TAR의 품질 추정이 아니라 연도·탁별 각 120대국 표본 결과다. 옥탁의 재생 실패 원인은 아직 분류하지 않았다. 자세한 수치는 `docs/validation/majsoul-replay-audit.json`에 있다.
- 최종 epoch 타패 모방 일치율은 학습 45.19%, 2025 검증 46.00%, 2026 보류 테스트 46.25%다.
- 동일한 64반장 비교에서 모델 평균 순위 3.42·평균 점수 변화 -16,758·화료율 2.52% (16/635국), 방총 론 청구 103/635국이었다. 규칙 기반 상대군은 평균 순위 2.19·평균 점수 변화 +5,586·화료율 23.15% (441/1,905국), 방총 론 청구 269/1,905국이었다.

양쪽 모델 모두 규칙 기반 정책보다 비교 결과가 크게 낮다. 사람 타패 모방률은 성능 향상을 뜻하지 않는다는 한계를 확인했다. 두 체크포인트는 재현·분석을 위한 `.research/models/`에만 두고 Git에 넣지 않는다. 작혼 데이터 카드는 `other`이며 사용 권리 미확인이고, 천봉 데이터 카드도 `other`이며 원천 저장소는 로그에 CC BY 권리를 부여하지 않는다고 명시한다. 원본 로그·플레이어 식별자·모델 가중치는 커밋하거나 푸시하지 않는다.

집계 결과 파일: `docs/validation/majsoul-training.json`, `majsoul-replay-audit.json`, `majsoul-model-comparison.json`, `tenhou-training.json`, `tenhou-model-comparison.json`, `tenhou-dataset-manifest.json`.

## 교차 출처 80/20 혼합 정책 비교 (2026-11-05)

천봉 가중치 80%와 작혼 가중치 20%를 특징별 선형 결합한 `tenhou-mjsoul-mix-80-20-v1`을 추가했다. 두 기존 단독 정책과 혼합 정책을 모두 작혼 규칙·반장전에서 같은 시드(20261105–20261120)·좌석·`rule-based-v1` 상대에 대해 각각 64경기씩 비교하고 모든 대국을 재생 검증했다. 체크포인트 SHA-256과 혼합 정책의 정규 직렬화 해시를 보고서에 기록했다.

| 정책 | 평균 순위 | 평균 점수 변화 | 화료율 | 방총 론 청구/국 | 기준선 상대 평균 순위 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 천봉 단독 | 3.56 | -21,786 | 1.73% (11/636) | 0.186 | 2.15 |
| 작혼 단독 | 3.42 | -16,758 | 2.52% (16/635) | 0.162 | 2.19 |
| 천봉 80% + 작혼 20% | 3.53 | -18,114 | 1.16% (7/606) | 0.142 | 2.16 |

80/20 혼합은 천봉 단독보다 평균 순위와 점수 변화가 약간 나았지만 작혼 단독보다 나빴고, 세 정책 모두 규칙 기반 상대군보다 크게 낮았다. 따라서 혼합이 성능을 개선했다고 판단하지 않는다. 비율은 튜닝되지 않은 한 번의 실험값이며, 천봉·작혼 데이터 권리가 해결될 때까지 체크포인트는 로컬에만 둔다. 결과: `docs/validation/imitation-policy-mixture-comparison.json`.
